01 / WHY RAG

从分散资料，走向可追溯的知识工作台

文档分散在不同仓库时，查找资料往往需要反复翻阅。智枢把这些资料接入同一个工作台：你选好知识范围、提出问题，系统检索相关内容并生成带来源的回答。整理会议、报告和申请时，也可以参考已有资料。

RAG 是什么？

可以把它理解为一次“带着资料的问答”。

系统先从你选定的知识库中查找相关片段，再让模型参考这些片段回答。这不等于重新训练模型，也不表示回答一定正确；原文和引用是你检查结论的依据。

02 / ARCHITECTURE

两条 Python 链路，一个知识底座

同步负责准备资料，提问负责查找和组织内容。两步由你分别发起，仓库更新后也需要手动同步。

资料入库

选择资料仓库与版本读取文本按文件规则筛选分成片段保留文件与行号建立索引向量化并保存

任务回答

提出问题选定知识范围查找片段语义与关键词检索组织内容按任务生成结果核对依据阅读引用与原文

回答模型与嵌入模型分别配置。引用链接固定到同步时的提交；失败的同步不会覆盖之前的索引。

04 / IMPLEMENTATION

系统如何组织资料和任务

  • 前端沿用 HTML / CSS / JavaScript，无需前端构建工具；业务编排全部在 Python 后端。
  • FastAPI 提供知识源管理、手动同步、工作流执行和源码查看接口。
  • SQLite 保存完整索引快照；向量相似度与 BM25 在 Python 中计算，适合单机小型知识库。
  • 只读取仓库文本，不运行 GitHub 中的程序；知识内容不能注册或覆盖工作流。
  • 本版默认仅配置模式，模型调用、仓库同步和工作流执行需要显式开启。
05 / GET STARTED

从一份资料、一个问题开始

  1. 下载项目，填写模型配置并启动服务。
  2. 在“GitHub 知识库”添加资料仓库，保存后点击“同步知识库”。
  3. 看到“已同步”后，进入“知识问答”输入一个具体问题。
  4. 查看回答下方的资料片段，打开原文核对，再保存需要的结果。

QUESTIONS & ANSWERS

使用前，你可能还想了解

资料会保存在哪里？

文件片段和向量保存在运行机器的 SQLite 数据库中。同步时，文本会发送到你配置的嵌入服务；生成回答时，相关片段会发送到回答模型。

能否直接读取 PDF、录音或群聊？

目前主要读取 GitHub 中的 UTF-8 文本与代码。PDF、Word 和图片需先转为文本；会议与群消息需要手动粘贴文字，尚未接入录音转写或实时群聊。

找不到答案时怎么办？

先确认选中的仓库已同步且包含相关资料，再把问题写得更具体。若原始资料没有答案，需要补充文档，不能仅靠调整提问获得可靠依据。
