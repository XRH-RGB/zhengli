OMNIHUB / PROJECT BRIEF

智枢 OmniHub
让企业知识成为工作的依据。

以 GitHub 仓库为知识源，以 RAG 为核心，将文档问答与七类办公场景接入可维护的 Python 工作流。

进入知识工作台 →查看项目源码 ↗
01 / WHY RAG

从分散资料，走向可追溯的知识工作台

文档分散在不同仓库时，查找资料往往需要反复翻阅。智枢把这些资料接入同一个工作台：你选好知识范围、提出问题，系统检索相关内容并生成带来源的回答。整理会议、报告和申请时，也可以参考已有资料。

从问题出发找到资料，再回到原文核对，让知识更方便地用在日常工作中。

02 / ARCHITECTURE

两条 Python 链路，一个知识底座

资料入库

GitHub 仓库 / 指定版本文本筛选保留行号分块批量嵌入SQLite 快照

任务回答

问题 + 选定知识库向量与 BM25 检索融合排序Python 场景函数回答 + 文件引用

回答模型与嵌入模型分别配置。引用链接固定到同步时的提交；失败的同步不会覆盖之前的索引。

03 / WORKFLOWS

七类场景，七个 Python 模块

场景知识依据与输出源码
知识检索问答根据文档和代码回答，附文件与行号。documents.py
知识出题与答题反馈从知识库出题，附参考答案或学习反馈。exam.py
会议纪要整理结合会议文字和项目资料，提取决议与待办。meeting.py
日报与周报草稿结合工作记录及报告规范生成草稿。report.py
OA 制度与申请辅助检索制度，整理字段与申请草稿。oa.py
群消息整理整理粘贴消息，提取主题和待办。messages.py
知识学习与培训建议按学习目标推荐仓库材料和练习。training.py

本版接收文字材料。录音转写、飞书实时接入、消息推送和 OA 自动提交未接入；相关场景输出供人工核对的草稿。

04 / IMPLEMENTATION

系统如何组织资料和任务

  • 前端沿用 HTML / CSS / JavaScript，无需前端构建工具；业务编排全部在 Python 后端。
  • FastAPI 提供知识源管理、手动同步、工作流执行和源码查看接口。
  • SQLite 保存完整索引快照；向量相似度与 BM25 在 Python 中计算，适合单机小型知识库。
  • 只读取仓库文本，不运行 GitHub 中的程序；知识内容不能注册或覆盖工作流。
  • 本版默认仅配置模式，模型调用、仓库同步和工作流执行需要显式开启。
05 / GET STARTED

从一份资料、一个问题开始

  1. 下载项目，填写模型配置并启动服务。
  2. 在“GitHub 知识库”添加资料仓库，保存后点击“同步知识库”。
  3. 看到“已同步”后，进入“知识问答”输入一个具体问题。
  4. 查看回答下方的资料片段，打开原文核对，再保存需要的结果。
