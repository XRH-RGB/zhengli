再多了解一点

输入问题后，系统具体做了什么？

先在选中的知识库中，结合语义相近程度和关键词查找片段；再挑选相关内容交给回答模型。模型同时看到你的问题、任务要求和这些片段，最后返回回答与资料引用。

检索范围决定可以查哪些资料，检索片段数量决定最多参考多少条。片段不是越多越好，先用默认值，再根据来源是否相关作调整。

“知道这个词”和“找到这份资料”有什么区别？

模型可能熟悉通用概念，但不一定知道你的项目约定。比如“如何提交申请”，需要仓库中实际的申请制度；仅有一份项目介绍，无法提供具体审批条件。

查不到时先确认资料是否存在、是否被文件规则选中、是否同步成功，再调整问题。换一种说法不能补齐缺失的事实。

同一个问题，为什么更新资料后需要重新同步？

问答使用本地已经建立的索引，不会每次都重新读取 GitHub。仓库文件修改后，重新同步才能把新内容加入索引。来源链接固定到当次同步的版本，便于确认回答依据的是哪一份资料。

提问时需要把前面的内容再说一遍吗？

当前每次请求独立处理，不会自动带上上一轮对话。继续追问时，请把对象和条件写完整，例如“针对刚才提到的模型更换，请说明知识库同步步骤”，并明确所指的模型和配置。

更清楚的写法是：“我将嵌入模型从 A 换成 B，服务已重启，接下来如何更新已有知识库？”其中 A、B 请替换为实际模型名。

文件和片段有什么区别？

长文档会被分成较小的片段，供系统检索。一个文件可能对应多个片段，片段数量不代表文档质量。

维护更新

什么时候需要重新同步？

仓库资料修改后，或更换嵌入模型后，手动同步一次。同步失败时，之前成功建立的索引会保留。

    第一次使用怎么做

    1. 准备环境。下载并解压项目，在能看到 requirements.txt 的文件夹打开 PowerShell，按下方说明安装依赖。
    2. 填写模型。复制 .env.example 为 .env，填写回答模型和嵌入模型的接口地址、名称及密钥。
    3. 开启运行。把 EXECUTION_ENABLED 改为 true，保存配置后启动服务。
    4. 添加资料。进入“GitHub 知识库”，填写仓库地址并保存，再点击“同步知识库”。
    5. 开始提问。看到“已同步”且文件数大于 0 后，进入“知识问答”，选择仓库并输入问题。

    如果按钮不可用，先检查顶部连接状态和运行开关。修改 .env 后需要重启服务。

    照着步骤操作

    先分清三种密钥，避免填错位置
    模型服务密钥
    填写在 .env 的 LLM_API_KEY 和 EMBEDDING_API_KEY，用于访问回答和嵌入服务。
    GitHub 令牌
    填写在 .env 的 GITHUB_TOKEN，用于读取仓库。浏览器登录 GitHub 不会把登录状态传给后端。
    系统访问密钥
    对应 APP_API_KEY。只有设置过这一项，才需要在本页的“系统访问密钥”输入框填写相同内容。
    1. 下载、配置和启动（Windows）
    1. 在项目仓库点击 Code → Download ZIP，下载后解压。进入能看到 app 和 requirements.txt 的目录，在资源管理器地址栏输入 powershell 并按回车。
    2. 确认已安装 Python 3.11 或更新版本，在窗口中逐行输入：
      python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
    3. 填写 LLM_BASE_URL、LLM_MODEL、LLM_API_KEY，以及对应的 EMBEDDING_ 三项。模型名、地址和密钥从所用服务商处获取；接口根地址不要附加 /chat/completions 或 /embeddings。将 EXECUTION_ENABLED 改为 true，按 Ctrl+S 保存。
    4. 在原窗口输入：
      .\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
      保持窗口打开，在浏览器访问 http://127.0.0.1:8000。设置过系统访问密钥时，在本页输入相同的密钥并点击“连接”。
    2. 添加资料并完成第一次问答
    1. 点击“GitHub 知识库”，粘贴仓库首页地址，例如 https://github.com/XRH-RGB/zhengli。分支第一次可留空，文件规则可保留默认值。
    2. 点击“保存知识源”，在下方出现的仓库卡片中点击“同步知识库”。看到“已同步”且文件数、片段数大于 0 后继续。
    3. 进入“知识问答”，选中已同步的仓库，输入具体问题，例如“更换嵌入模型后需要做哪些操作？”，点击“检索并回答”。
    4. 展开回答下方的“查看原始片段”，点击文件链接核对内容。需要保存时点击“复制回答”。

    查询业务资料时，请添加实际存放这些资料的仓库。浏览器登录 GitHub 不会自动授权后端读取私有仓库，私有仓库需配置 GITHUB_TOKEN。

    3. 整理会议纪要、周报或群消息
    1. 进入“Python 工作流”，选择任务，例如“会议纪要整理”。
    2. 填写要求，例如“列出讨论结论、负责人和截止时间，不明确的内容标为待确认”，再粘贴会议文字记录。
    3. 选择相关的已同步知识库，点击“运行工作流”。
    4. 核对结果中的人名、数字、日期和引用，点击“复制结果”，再粘贴到文档或办公系统中。

    使用工作流无需编辑 Python 代码。发送消息和提交申请仍由你在相应系统中完成。

    4. 更新资料、修改配置和关闭服务
    1. GitHub 文档有变化时，回到仓库卡片手动点击“同步知识库”，问答才会使用更新后的资料。
    2. 修改 .env 后，在服务窗口按 Ctrl+C 停止，再运行上面的启动命令。更换嵌入模型或其接口地址后，重新同步知识库。
    3. 刷新页面前先复制需要保留的回答。结束使用时，在服务窗口按 Ctrl+C；下次只需重新启动服务。
