# 智枢使用指南

第一次使用按第 1～4 节操作。以后通常只需要启动服务、同步更新过的资料，再提问或整理材料。

## 1. 下载项目并准备环境

1. 打开[项目仓库](https://github.com/XRH-RGB/zhengli)，点击绿色的 **Code** 按钮，再点击 **Download ZIP**。
2. 在下载文件上点击右键，选择“全部解压”。打开解压后的文件夹，继续进入内层目录，直到能看到 `requirements.txt` 和 `app` 文件夹。
3. 点击资源管理器顶部的地址栏，输入 `powershell`，按回车。后面的命令都在这个窗口逐行输入，每行完成后再输入下一行。
4. 输入 `python --version`，确认版本为 3.11 或更新版本。如果找不到 Python，先安装相应版本，并在安装时选择将 Python 加入 PATH，再重新打开 PowerShell。
5. 创建独立的 Python 环境，然后安装项目依赖：

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

安装结束并重新出现输入提示符后，继续下一步。如果出现错误，先处理错误再继续。这里使用完整的 Python 路径，无需执行虚拟环境激活脚本。

## 2. 填写模型配置

在刚才的窗口输入：

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

这会在没有配置文件时创建 `.env`，然后用记事本打开。逐项替换等号右侧的值，保留字段名称。若手动另存为，确认文件名是 `.env`，没有多出 `.txt` 后缀。

| 字段 | 怎么填写 |
| --- | --- |
| `LLM_BASE_URL` | 回答模型的接口根地址，通常以 `/v1` 结尾；不要在末尾再加 `/chat/completions` |
| `LLM_MODEL` | 服务商提供的、账号可以调用的回答模型名称 |
| `LLM_API_KEY` | 对应服务的 API 密钥；不需要密钥的本地兼容服务可留空 |
| `EMBEDDING_BASE_URL` | 嵌入服务的接口根地址，不要在末尾再加 `/embeddings` |
| `EMBEDDING_MODEL` | 用于文本向量化的嵌入模型名称，需支持嵌入接口 |
| `EMBEDDING_API_KEY` | 嵌入服务的密钥，是否与回答模型共用密钥取决于服务商 |
| `EXECUTION_ENABLED` | `false` 表示只配置；准备同步资料和生成内容时改为 `true` |
| `GITHUB_TOKEN` | 公开仓库可先留空；私有仓库填入具有目标仓库读取权限的令牌 |
| `APP_API_KEY` | 只在本机使用可留空；远程使用时设置，在界面输入相同值 |

回答模型负责组织语言，嵌入模型负责把问题和文档转换成便于检索的向量，两项都需要配置。它们可以来自不同服务商。地址、模型名和密钥请从各自服务的控制台或接口说明中获取。

填写完成后按 `Ctrl+S` 保存，再关闭记事本。其他参数首次使用可以保留默认值。后续修改 `.env` 后，需要停止并重新启动服务。

## 3. 启动并打开工作台

1. 在项目根目录的 PowerShell 窗口输入：

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
   ```

2. 等待启动完成，在浏览器地址栏输入 `http://127.0.0.1:8000`。运行期间保持 PowerShell 窗口打开。
3. 点击左侧“模型与运行配置”，查看两个模型的名称。若显示“未配置”，返回 `.env` 补全后重启。
4. 如果设置了 `APP_API_KEY`，在“系统访问密钥”输入相同值，点击“连接”。这里只填系统访问密钥，模型服务密钥保存在 `.env` 中。
5. 如果右上角显示“配置模式”，将 `.env` 中的 `EXECUTION_ENABLED` 改为 `true`，保存并重启，再点击“刷新状态”。

“服务已连接”只表示工作台连上了后端，模型是否可用需要通过同步和提问确认。直接双击 `index.html` 可以查看页面，但问答功能需要从上述服务地址打开。

## 4. 添加第一份知识库

1. 点击左侧“GitHub 知识库”。在“GitHub 仓库地址”粘贴仓库首页地址，例如 `https://github.com/XRH-RGB/zhengli`。不要填写单个文件或上传页面的地址。
2. “分支、标签或提交”第一次可以留空，使用默认分支。如果只想读取某个版本，再填写对应名称或提交编号。
3. 在“要读取哪些文件”填写文件规则：

   | 想读取的资料 | 填写示例 |
   | --- | --- |
   | Markdown 文档 | `**/*.md` |
   | Markdown 和纯文本 | `**/*.md, **/*.txt` |
   | 文档与 Python 代码 | `**/*.md, **/*.txt, **/*.py` |
   | docs 目录下的 Markdown | `docs/**/*.md` |

   前三种也会匹配根目录文件。第一次建议只同步少量相关文档。当前不直接解析 PDF、Word 或图片，需要先整理为 UTF-8 文本。

4. 点击“保存知识源”。页面下方出现仓库卡片，状态为“待同步”。这一步只保存地址和读取范围。
5. 点击卡片上的“同步知识库”。系统会读取匹配文件并调用嵌入服务，耗时取决于文件数量和接口速度；处理中保持页面打开。
6. 同步完成后，检查卡片是否显示“已同步”，文件数和片段数是否大于 0。若提示跳过文件或没有匹配内容，先检查文件格式和匹配规则。

项目仓库可以用来练习问答；查询公司制度或业务资料时，需要添加实际存放这些内容的仓库。将系统源码放到 GitHub，与把资料同步到知识库，是两项独立操作。

## 5. 提问并核对来源

1. 点击“知识问答”，在“检索范围”选中已同步的仓库。多选时按住 `Ctrl` 再点击其他仓库；Mac 使用 `Command`。
2. 输入具体问题。例如，使用本项目作为知识库时，可以问：“更换嵌入模型后，需要做哪些操作？”
3. “检索片段”先保留默认的 6 条，点击“检索并回答”。等待回答显示在下方。
4. 展开“查看原始片段”，核对回答是否与资料一致；点击文件链接，查看同步时对应版本的原文和行号。私有仓库链接需要有访问权限的 GitHub 账号。
5. 点击“复制回答”，把回答和来源链接粘贴到需要的位置。刷新页面前先保存有用的内容。

如果找不到依据，先检查资料是否已同步、仓库是否选对，再把问题写得更具体。检索排序分用于排列相关片段，不代表回答的正确概率。

## 6. 使用工作流整理材料

1. 点击“Python 工作流”，选择任务，例如“会议纪要整理”。
2. 在“任务要求”填写想得到的内容，例如：“整理本次项目会议，列出已确定的事项、负责人和截止时间；不明确的内容列为待确认。”
3. 在“会议文字记录”粘贴实际记录。其他任务按输入框名称填写工作记录、申请信息或群消息等材料。
4. 在“知识范围”选中与材料有关、已同步的仓库，点击“运行工作流”。
5. 在下方“工作流结果”核对人名、数字、时间和引用，点击“复制结果”，再粘贴到文档或办公系统中。

工作流不需要你手动编辑 Python 代码，右侧源码供需要了解实现的人查看。输出是草稿，发送消息或提交申请仍由你在相应系统中完成。

## 7. 更新资料和再次启动

- **资料有变化**：先在 GitHub 更新文件，再回到仓库卡片点击“同步知识库”。系统不会自动追踪新提交。如果选择了固定提交，需添加指向新版本或分支的知识源。
- **改变读取范围**：按新规则添加知识源并同步，确认可用后再移除旧项。移除只删除本地知识库及索引，不会删除 GitHub 文件。
- **更换嵌入模型**：编辑 `.env`，重启，再逐个同步需要使用的知识库。上游模型权重变化时也应重新同步。
- **关闭系统**：回到 PowerShell 按 `Ctrl+C`。下次在同一目录执行第 3 节的启动命令即可，无需重新创建环境。
- **保留数据**：`.env` 和 `data/` 留在本地，备份数据库前先停止服务。不要把配置密钥、数据库或 `.venv/` 放进公开仓库。

## 8. 常见问题

| 遇到的情况 | 处理方法 |
| --- | --- |
| 找不到 requirements.txt 或 app | 当前目录不对，进入能看到这些文件的项目根目录，再打开 PowerShell |
| 页面无法连接 | 检查服务窗口是否仍在运行，浏览器是否打开服务地址，端口是否与启动命令一致 |
| 8000 端口被占用 | 将启动命令中的端口改为 8001，再访问 `http://127.0.0.1:8001` |
| 同步或运行按钮不可用 | 查看顶部连接状态，连接服务、开启运行开关并重启；如果已有任务，等待完成 |
| 系统访问密钥无效 | 在配置页输入与 `.env` 的 `APP_API_KEY` 相同的值，再点击“连接”；刷新后需重新输入 |
| GitHub 读取失败或限流 | 检查地址、版本、网络和令牌权限；限流时等待恢复或配置有效令牌。浏览器已登录不等于后端获得授权 |
| 模型请求报错或超时 | 检查接口地址、模型名、密钥及服务额度，确认嵌入模型支持嵌入接口，修改后重启 |
| 没有可用文件 | 检查匹配规则和编码，PDF、图片、大文件及被排除的路径不会入库 |
| 提示重新同步 | 当前嵌入配置与旧索引不同，到知识库页面重新同步对应仓库 |
| 回答还是旧内容 | 手动同步仓库，并确认读取的分支或提交，回答链接固定到同步时的版本 |
| 刷新后回答不见了 | 当前版本不保存会话历史，有用的内容请先复制到文档 |

验证情况见[验证记录](DELIVERY_STATUS.md)。准备正式使用前可参照[检查清单](ACCEPTANCE.md)逐项确认。
